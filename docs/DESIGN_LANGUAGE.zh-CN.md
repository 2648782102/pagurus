# Pagurus 设计语言

本文是 Pagurus 前端的**视觉与交互宪法**：它规定两个 surface 共享什么、各自允许偏离什么，以及所有面板必须遵守的交互原语。新增组件、改样式、做迁移前先读这份；与本文冲突的旧代码视为待清理项，不是先例。

它不是 API 契约，不参与 guardrail 校验；事实源仍是 `docs/openapi.yaml` 与已接受 ADR。

## 一句产品定义

**Pagurus 是海螺（Conchbase）的壳**：一个人通过它向 Agent 提出目标、阅读回答、检查证据。Conchbase 独占执行、状态与权限；Pagurus 只呈现已发布事实，并提交 Runtime 已接受的操作。

由此推出一条视觉公理：

> **界面呈现事实，不制造事实。** 任何在 Runtime 尚未确认时写下的断言（“没有项目”“已到最新”“执行成功”）都是设计错误，不只是文案问题。

## 两个 surface，一个品牌

Pagurus 一个 build、两个入口，见 `src/app/surface.ts`：

| surface | 入口 | 使用者 | 任务 | 气质 |
|---|---|---|---|---|
| **Agent 应用** | `?surface=agent` | 人 | 提问、阅读、判断 | 安静、编辑感、留白、衬线正文 |
| **调试台** | `/`（原有 hash 路由） | 开发者 | 扫描状态、定位、控制 | 密集、规则、仪表盘、等宽标签 |

关系不变量（长期方向已定）：

1. **Agent 应用是最终产品形态**；调试台是开发期工具。
2. 调试台不会永远独立存在。能力成熟后，它以可收起、权限受限的「检查 / 证据」模式**融入 Agent 应用**，而不是作为第二个产品长期并列。
3. 因此两者是**同一品牌的两种模式**，不是两个设计系统。允许密度与语气不同，不允许颜色语义、状态语义、控件行为互相矛盾。
4. 任何新建用户可见能力，默认落在 Agent surface；只有在排查 Runtime 时才加调试台入口。
5. **权重不对称，已拍板**：以 Agent 为主。语义命名、默认样式、组件默认值都取 Agent 侧；调试台是 `surface="console"` 的例外适配，不是与 Agent 对等的第二套。调试台的卡片密度与专属视图可以保持现状，不再投入对等的视觉设计。

隐喻：Pagurus 是寄居蟹，Agent 是蟹，每段对话是它占据的一个壳。Agent 侧的会话栏读起来应是**一排壳**（可辨认、可切换的容器），不是导航菜单；这个隐喻指导形状与分组，不要求插画或拟人化。

## 共享层与偏离层

### 所有 surface 必须共享

| 层 | 约束 |
|---|---|
| **颜色语义** | signal / caution / danger / neutral 的含义与方向一致。绿=可用或成功，琥珀=需要注意，红=失败或拒绝，钢蓝=身份与链接，rust=唯一主操作。**具体色值可因表面明度微调，含义不可翻转。** |
| **状态机与文案** | 见下文「异步状态原语」；同一状态在所有面板用同一套词与 `aria`。 |
| **控件行为** | 主操作唯一、危险操作需明确、禁用原因可见、键盘可达、focus 可见。 |
| **排版基线** | 正文与代码分离：人类语言用 sans/serif，标识符、摘要、digest、ID 用等宽；`font-synthesis: none`。 |
| **数据边界** | 不读写私有文件与数据库；只呈现 Runtime 已发布事实，来源在界面上可辨。 |

### 允许各自偏离

| 维度 | Agent 应用 | 调试台 |
|---|---|---|
| 底色 | 矿物纸 `#f3f4f1` 类（**主**） | 冷灰仪器底 `#e9edee` 类（例外适配） |
| 结构 | 单栏阅读 + 右侧上下文抽屉 | 左侧工作区导航 + 多栏证据区 |
| 密度 | 一屏一件事，测量宽度 `--ag-measure` | 一屏多事实，允许表格与长列表 |
| 正文 | **仅回答正文**用衬线（中文在前） | 全 sans + mono 标签 |
| 装饰 | 无渐变、无内容卡阴影 | 无渐变、无内容卡阴影（同样禁止） |
| 主操作色 | 继承 rust | rust |

### 明确禁止（两 surface 通用）

- 渐变背景、玻璃拟态、纯装饰性阴影、全大写微标签。
- 同一屏出现两个视觉等权的“主按钮”。
- 用颜色单独承载状态（必须同时有文字或形状）。
- 在 token 已定义语义的地方写死颜色；新增颜色先进 token 层。
- 把「没读到」渲染成「没有」（见下一节）。

## 异步状态原语

这是**横切规则**，不属于某个面板。任何「请求 Runtime → 渲染结果」的区域，都必须显式区分以下状态；不得把多种状态压成「有数据 / 没数据」二分。

| 状态 | 判定 | 展示 | `aria` |
|---|---|---|---|
| `checking` | 未确认对端支持该契约 | 「正在检查…」 | `status` |
| `loading` | 已发请求、未收到 | 「正在读取…」；计数显示 `—` | `status` |
| `ready-empty` | **读到了，确实为空** | 「Runtime 尚未发布…」；计数 `0` | 普通文本 |
| `ready-data` | 读到了，有内容 | 真实数据 | — |
| `partial` | 部分成功（分页未完、某子请求失败） | 数据 + 明确缺口与继续方式 | `status` |
| `error` | 读取失败 | 原因 + 可执行的重试 | `alert` |

规则：

1. `loading` 与 `ready-empty` 的文案、计数表现**不得相同**。前者是未知，后者是事实。
2. 多个子请求时，允许各区域独立处于不同状态；**整体状态不得掩盖已到达的部分数据**。
3. 自动刷新不得把已显示的 `ready-data` 退回空白；刷新中保留旧数据并标注「同步中」。
4. 新增面板先列出它的六个状态再写 JSX；只写「有 / 无」两分支的实现视为未完成。

历史依据：组织台曾把首次读取中的空列表渲染成「Runtime 尚未发布项目」并显示 `0 个项目`，数据 4 秒后自行出现。这不是文案瑕疵，是缺失 `loading` 档位；回归测试在 `tests/organization-console.test.tsx`。

## Token 分层（目标结构，非现状）

现状有两份平行调色板：`src/styles/tokens.css`（调试台 `--*`）与 `src/styles/agent-tokens.css`（Agent `--ag-*`）。它们是**palette**，不是 design token。目标是在其上加一层语义：

```
palette（各自色值，--ag-* 为主、--* 为例外）
   └─ semantic token（--surface / --text / --border / --state-* / --accent）
        └─ component（只引用 semantic token，不认识 palette）
```

- 两份 palette 继续允许不同的底色与中性阶；**状态语义必须共享同一组名字**。
- 语义层的**默认值取 Agent**；调试台在自己的根元素上覆盖同名 token，不反向要求 Agent 迁就。
- 组件不得直接引用 palette 色值，更不得写死 `#xxx`。
- 现状有约 96 处硬编码颜色、且注释声明的「无圆角 / 无阴影」被局部组件违反；这些是迁移债，按「先语义层、后逐组件收编」偿还，不要求一次改完。

## 组件边界（已决：A）

`src/shared/ui/primitives.tsx` 现有 `Button / Field / TextInput / Select / Textarea / Tag / StatusDot / Section / Disclosure / EmptyState / Notice`，但 Agent surface 目前只复用 `Notice`，其余自行实现。

**决定：A — 单组件库 + variant。** 理由：目标是 Agent 逐步吸收调试台，控件行为（尤其异步状态、focus、危险操作）必须同源；视觉差异用 variant 表达足够。

执行方式：

- **默认即 Agent**。`<Button>` 不传 `surface` 时就是 Agent 样式；调试台包裹在 `surface="console"` 的容器下才切换。不给调试台单独的默认分支。
- **视觉差异优先由语义 token 的 CSS 作用域表达**，而不是每个组件加 JS 分支：同一组件只写 `var(--surface)` / `var(--text)`，在 `.agent-app` 下解析为 Agent 值，在调试台根下解析为 console 值。JS `surface` prop 只用于结构或行为确实不同的地方（如密度、是否显示侧栏）。
- 组件不得直接引用 `--ag-*` 或 `--*`（palette），只引用语义层；这样新增 surface 只需补一份 palette alias。
- 迁移顺序：先让 shared primitives 只依赖语义 token → 再把 Agent 自建的按钮 / 输入 / Tag 逐个换回 shared → 最后删掉重复实现。**不得再新增第三份**。

旧决定记录：曾考虑 B（承认两套组件、永久双份维护），已否决。

## 品牌签名（最后做，不阻塞前面）

品牌目前只存在于文案（footer「Pagurus · 寄居蟹」、sidebar「配置在寄居蟹，执行由海螺负责」），用户看不到可辨识的形状或色签。

方向：从「壳 / rack of shells」推导**一个**可复用签名——候选是会话栏的壳形容器边界，或一枚 sea-glass 身份色用于当前会话标记。只选一个，用在关键处；不做插画、不做吉祥物、不铺满界面。

前置条件：共享语义 token 与组件边界已定。否则签名会被两套实现解释成两种样子。
